## 二、关键实现

- **ID**：`src/data/ids.ts` 纯 TS 生成 UUID v4 形态（`Date.now()` + 递增计数器 + 随机数），不引第三方依赖；实测 1000 次无重复。v1 迁移改用 `createStableId()`（UUID v5 形态、FNV-1a 派生），同一份旧数据在任何设备上迁移得到相同 ID。
- **审计字段**：`EntityMeta`（`id` / `createdAt` / `updatedAt` / `deletedAt?` / `legacyId?`），`TradeState` 增加 `schemaVersion: 2`、`revision`、`updatedAt`、`deviceId`。
- **软删除**：`state.ts` 中 `tombstone()` 只写 `deletedAt`，账户/股票删除级联子实体；重复删除不覆盖首次墓碑时间；所有统计函数过滤墓碑。
- **合并**：`merge.ts` 按 ID 取并集，`updatedAt` 新者胜，同时间戳删除优先；仅当双方都存在且内容不同（除 `updatedAt` 外字段有差异）才记录冲突。
- **迁移**：`migrate.ts` 用 `Map<number, string>` 重建账户/股票/交易/做T 的引用关系，孤儿实体丢弃，旧数值存入 `legacyId`；`detectStateVersion()` 区分 v1 / v2 / 未知版本，未知版本 fail-closed。
- **排序**：同日顺序改为 `date → legacyId ?? MAX_SAFE_INTEGER → createdAt → id`，保证迁移前后六项统计指标不回归。
- **同步**：`sync.ts` 载荷升到 `version: 2`，云端 v1（含裸 v1 状态）自动迁移；下载从“覆盖本机”改为 `mergeStates(local, remote)`，返回新增/删除笔数与冲突摘要。
- **冲突日志**：`repository.ts` 维护 `tradetrace/conflicts/v1`，最多 50 条，设置页合并下载后自动追加，重复冲突不重复记录。
- **存储键**：读 `tradetrace/state/v2`，不存在时回退 `tradetrace/state/v1`；迁移后立即写回 v2。读取结果区分空/损坏，损坏时禁止写盘。

## 三、偏离计划之处

1. **新增 `vitest.config.ts`**：本机 hosts 未映射 `localhost`，Vitest 启动报 `getaddrinfo EAI_FAIL localhost`；配置 `server.host = '127.0.0.1'` 后可正常运行。计划中未预见此项。
2. **`stock/[id].tsx` 额外展示 OCR 来源与成交时间**：按 Task 9 最后一条执行，仅当 `source === 'ocr'` 或 `time` 有值时显示。
3. **迁移 ID 由随机 UUID v4 改为确定性 UUID v5**：计划只写“UUID”，但两台设备各自迁移同一份 v1 数据会生成不同 ID，合并后整批重复、收益翻倍，因此改为按 `v1:<类型>:<旧ID>` 确定性派生。计划中的“UUID 匹配”断言相应改为 v5 形态。
4. **新增 `repository.test.ts`**：覆盖“损坏数据不写盘”“未知版本不写盘”“v1 迁移写回”“冲突日志去重”，计划中未列。

## 五、Code review 与修复

审查按 `superpowers:requesting-code-review` 执行，范围为基线 `0e053d7` 到工作区改动。发现 4 个 Critical、5 个 Important，已全部修复并补测试：

| 级别 | 问题 | 修复 |
|---|---|---|
| Critical | 本地 v2 JSON 损坏时被当作“无数据”，空状态覆盖原始数据 | `storage.ts` 用 `RawStateResult` 区分 ok/empty/corrupt；`repository.ts` 损坏或版本未知时不写盘 |
| Critical | 未知/未来版本落入 v1 分支，UUID 实体被丢弃后写回空状态 | 新增 `detectStateVersion()`，仅 v1/v2 走迁移与校验，未知版本 fail-closed |
| Critical | 两台设备各自迁移同一份 v1 数据会得到不同随机 UUID，合并后数据翻倍 | 新增 `createStableId()`（UUID v5），迁移按 `v1:<类型>:<旧ID>` 确定性派生 |
| Critical | `mergedProfit` 未校验父链，账户已删但股票新增时与 `accountProfit` 口径不一致 | 改为只统计账户与股票都存活的交易，并补回归用例 |
| Important | 声明 v2 但缺少实体数组的载荷被当成空状态合并 | `parsePayload` 增加 `isStateShape` 校验，非法返回 `null` |
| Important | 合并摘要只按活跃交易净差计算，删除被 `max(0)` 吞掉 | 改为分别统计新增与删除，文案为「新增 N 笔交易，删除 M 笔」 |
| Important | `linkedShares` 未过滤做T墓碑，出现“可关联但提交被拒” | 加 `!tt.deletedAt` |
| Important | 表单要求股息 > 0，导入的负股息（红利税）无法编辑保存 | 校验改为“非 0”，文案说明可填负数 |
| Important | 设置页在 `loadState` 完成前可合并，存在空状态覆盖风险 | 增加 `ready` 守卫并同步禁用按钮；确认弹窗在确认后关闭 |

已确认无需修改的审查意见：

- `pickWinner`（新者胜 / 同刻删除优先 / 双删取本地）与 `entityEqual`（排除 `updatedAt`）符合计划。
- 页面内 `state.transactions.filter(...).length` 与 `totalCost - cycleCost` 属展示派生，不另立统计口径。
- `computeDedupeKey` 不含 `stockId` 与 `time` 是计划既定规则，改动会改变协议语义，暂不调整。
