## 三、关键实现

- **三层纯函数**：`layout.ts`（纵坐标聚行带 + 表头列锚点归列）→ `parse-ths.ts`（行块字段抽取、方向判定、金额交叉校验）→ `normalize.ts`（名称归一、名称→ID、`TransactionInput` 组装）。不 import 任何 RN / Expo / AsyncStorage 模块。
- **方向只认文字**：`matchOperation()` 按操作列文本判定买入 / 卖出 / 股息 / 税补缴 / 银证转账 / 申购配号，金额符号仅用于交叉校验。
- **金额校验**：买入 `commission = |金额| − price × shares`，卖出 `commission = price × shares − 金额`；与费用列误差 > 0.02 时给「金额与价格×数量不一致」警告并保留费用列值，置信度下调。
- **截断处理**：价格/数量缺失直接跳过（`skipped.kind='无法识别'`）；金额缺失仍产出候选，警告「金额缺失，费用无法交叉校验」，`commission=0` 且置信度降到 0.6 以下，由导入确认页决定是否勾选。
- **股息行**：价格列写 0，原值写入 `note`（「价格列原始值 x（分红参数，未作为成交价）」）；税补缴统一 `type='股息'`、`dividend` 为负。
- **跨年**：每遇到 `YYYY-MM` 分组行更新年份，行内 `MM-DD HH:mm` 用所属分组年份，并校验日期不晚于 `today`。
- **股票名归一**：前缀剥离 `XD/XR/DR/*ST/ST/N/C/U`（名称长度 ≥ 3 才剥离，避免误伤两字名）。

## 四、偏离计划 / 与规格的差异

1. **账户头部识别正则修正**：计划代码 `/证券公司?/` 要求「证券公」或「证券公司」，无法匹配规格中的「浙商证券 *4768」，导致 `accountHint` 恒为空、计划自带的买入用例失败。已改为 `/证券(?:公司)?/`，与规格 6.3「头部可读到 浙商证券 *4768」一致。
2. **未执行两项导出**：本次仅新增纯 TS 解析器，无 UI/路由改动，按分派要求不跑 `export:web` 与 `expo export -p android`；`typecheck` 与全量测试已通过。计划 Task 5 列出的四道验证中这两项留待导入确认页（含 UI）任务执行时一并验证。
3. **截断行与规格的取舍**：规格 6.1 要求「行块字段缺失 → 不自动勾选」，7 节允许「跳过不完整行，或标记需补充截图」。本实现选择「保留候选 + 警告 + 低置信度」，不自动勾选交由确认页按 `warnings` / `confidence` 处理，未违反规格，但与「直接跳过」是两种可选路径。
4. **`note` 中价格原值按数值输出**：规格示例为 `8.580`，实现输出 `8.58`（`Number` 归一化后），语义一致、仅少了末尾 0。

## 六、遗留与后续

2. **仅覆盖浙商证券版式**：`ths_zheshang_v1`；出现新版式时新增模板 ID，不改本模板语义。
3. **尚未用 17 张真实截图验证**：规格第 12 节验收要求待 OCR POC 与导入确认页任务补齐（含跨图去重、账户预选、字段级准确率统计）。
