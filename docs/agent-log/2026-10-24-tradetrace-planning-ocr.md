# 交易复盘产品规划与同花顺OCR选型

## 背景

本次对话围绕 TradeTrace 仓库的产品与技术规划展开。仓库包含两个子项目：`lianghua`（Python + FastAPI 行情数据平台）与 `everything`（React Native + Web 交易记录客户端）。目标是为后续四项工作做规划：对接行情后端、图片识别导入交易记录、交易行为分析、复盘报告。

约束：暂不修改 `lianghua` 既有代码、暂不对接后端、新系统从零开始不迁移旧交易数据；客户端需同时支持 Web 与 Android。

## 决策记录

### D1. 服务端只做只读行情

- **选择**：`lianghua` 仅提供股票字典、日K、指数区间、数据状态与健康检查；不做截图解析、不存交易、不算收益、不生成报告。
- **备选方案**：服务端 OCR + 导入任务队列；交易数据集中存储。
- **理由**：用户确认截图离线解析；服务端保持“客观行情事实”，与客户端分析与报告解耦。
- **代价 / 风险**：客户端需自行承担 OCR 与解析；后续若端上精度不足，需另立项服务端兜底。
- **相关文档**：`lianghua/docs/行情数据服务规划.md`

### D2. 交易截图端上离线识别

- **选择**：OCR 在设备本地完成，截图不上传；`OcrEngine` 接口隔离引擎，解析层只消费“文本行 + 坐标”。
- **推荐引擎**：PaddleOCR PP-OCRv5 mobile（det + rec）经 ONNX Runtime 双端部署（Android `onnxruntime-react-native`，Web `onnxruntime-web`）。
- **备选**：Android ML Kit 中文识别（快速原型/备选）；Tesseract 仅原型。
- **排除**：云端 OCR/多模态大模型默认排除；端上 3B 级视觉大模型暂不适用。
- **理由**：中文+数字精度、有检测框利于版面重建、无 GMS 依赖、双端模型一致。
- **代价 / 风险**：RN 原生模块集成成本高；Web WASM 加载与性能需实测；Expo 58 / RN 0.88 兼容性需验证。
- **相关文档**：`everything/docs/交易截图OCR引擎选型分析.md`

### D3. 家庭局域网访问与客户端地址配置

- **选择**：后端部署在家里，仅局域网访问；客户端设置页配置服务地址（如 `http://<internal-host>:8000`），保存前调用 `/api/health` 测试；不使用 `localhost`（Android 会指向手机自身）。
- **备选方案**：公网 + 鉴权；VPN/Tailscale。
- **理由**：服务无鉴权、单用户；家庭局域网最简单且不暴露公网。
- **代价 / 风险**：家庭 IP 变化需固定 IP/DHCP 绑定；Web 端需 CORS 白名单。
- **相关文档**：`lianghua/docs/行情数据服务规划.md`、`everything/docs/交易记录与复盘产品规划.md`

### D4. P0 先做数据模型 v2

- **选择**：交易 ID 改 UUID、软删除、`source`/`sourceRef`、`dedupeKey`、实体级合并；先于行情对接、OCR、分析与报告。
- **备选方案**：继续使用设备自增数字 ID + 整包覆盖同步。
- **理由**：多端合并与服务端对接时数字 ID 必冲突；整包覆盖会丢数据。
- **代价 / 风险**：需要 v1→v2 无损迁移与测试；短期不能直接做新功能。
- **相关代码**：`everything/src/data/types.ts`、`everything/src/data/`（本次未改代码）

### D5. 导入是“候选 + 人工确认”，绝不自动入库

- **选择**：OCR 结果只作候选；低置信字段留空/高亮；确认页可逐字段编辑、勾选、忽略、合并重复。
- **理由**：错账会污染收益与分析；宁可少识别，不可错识别。
- **相关文档**：`everything/docs/交易记录与复盘产品规划.md`

### D6. 同花顺解析规格（首期）

- **选择**：单一模板 `ths_zheshang_v1`，兜底 `ths_generic_v1`；解析三列三行行块。
- **关键规则**：
  - 截图无股票代码，只有名称；用本地股票字典映射，处理 `XD/XR/DR/ST` 前缀。
  - 买入金额为负、卖出为正；方向以文字为准，金额符号只作交叉校验。
  - 版式 A 金额含费用，可反推 `commission`；费用异常/缺失标记待确认。
  - 股息行价格列是分红参数、数量为 0，**不是成交价**；金额进 `dividend`。
  - `股息红利税补缴` 记为负股息，note 标明来源。
  - `银行转存/转取`、`申购配号` 跳过并提示；不计入收益。
  - 多张截图大量重叠，按 `名称+日期+类型+数量+价格+费用` 跨图去重。
- **相关文档**：`everything/docs/同花顺对账单截图解析规格.md`

### D7. 复盘报告“事实与表达分离”

- **选择**：报告数字全部由本地 `stats.ts` 计算；模板渲染保证确定性；LLM 仅可选润色，渲染后做数字校验，默认关闭。
- **理由**：避免模型篡改数字；报告必须可追溯到交易。
- **相关代码**：`everything/src/data/stats.ts`、`everything/src/data/types.ts`（本次未改代码）

### D8. 首期范围收敛为同花顺

- **选择**：雪球、腾讯自选股暂缓；现有 17 张同花顺样本作为基准集。
- **理由**：先把一家券商的离线导入闭环打通，再扩展模板。
- **相关文档**：`everything/docs/交易记录与复盘产品规划.md`

## 废弃方案

### 放弃：服务端 OCR + 导入任务队列

- **曾尝试**：在服务端做截图上传、`ImportJob`、OCR、候选返回。
- **放弃原因**：用户要求离线优先；截图不应离开设备；服务端职责收窄。
- **若将来重启需注意**：需用户显式知情开启、隐私评审、上传安全与临时文件清理。

### 放弃：云端 OCR / 云端多模态大模型作为默认路径

- **放弃原因**：违反离线与不上传硬约束；成本、限流与隐私风险。
- **若将来重启需注意**：只能作为用户显式开启的兜底。

### 放弃：端上 3B 级视觉大模型

- **放弃原因**：模型体积、内存、耗电与 Expo RN 集成成本不适合当前阶段。

### 放弃：Tesseract 作为生产主引擎

- **放弃原因**：中文混排、小字号与表格版面能力弱；仅保留为 Web 原型/兜底。

### 放弃：长江证券版式模板

- **曾尝试**：为样本 19 设计 `ths_changjiang_v1`（`金额/税费`、无符号金额、月/年分离）。
- **放弃原因**：用户删除该样本，首期只做浙商版式。
- **若将来重启需注意**：金额为毛额、费用可能缺失，不能复用浙商金额语义。

### 放弃：视频通话干扰样本

- **放弃原因**：含人脸/姓名等隐私干扰；用户删除，不作为基准样本。
- **若将来重启需注意**：解析需裁剪表格区域，但不应把该图用于评测。

### 放弃：依赖颜色或金额符号判断方向

- **放弃原因**：深色/浅色主题、不同版式下颜色与符号不一致；改为文字优先。

### 放弃：把股息行价格当作成交价

- **放弃原因**：股息行数量为 0，价格列是分红参数，`price × shares` 不成立。

## 约束

- 技术：Expo 58 / RN 0.88；新增原生模块需 Dev Client/prebuild，不能用 Expo Go；Web 需处理 WASM 与模型加载。
- 合规/隐私：截图不上传；不保存完整资金账号；样本仅本地使用；归档不含真实金额与账号。
- 业务口径：总收益 = 持仓收益 + 清仓收益；股息计入清仓收益；负股息需同步 `stats.test.ts`。
- 项目纪律：不修改 `lianghua` 既有代码；本期不做后端对接；新系统不迁移旧数据。
- 网络：仅家庭局域网，无鉴权，禁止公网暴露；CORS 使用白名单。
- 文档命名：拆分文档不使用 `lianghua` / `everything` 作为文件名。
