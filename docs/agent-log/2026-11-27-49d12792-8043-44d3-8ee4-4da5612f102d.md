# quant 个股详情复权切换

> 归档规则：只记录对话中真实出现过的内容，每条附原文依据；不编造、不遗漏、不臆想、不添油加醋。

## 会话摘要

给 quant 的个股详情页加「后复权 / 不复权」价格口径切换。后端接口加 `adjust` 参数并按同口径重算均线，前端右上角新增切换按钮、整页一起换口径；落盘结构不变，不引入前复权。

## 2026-11-27 09:37

- **[决策·已定]** 切换口径时**整页一起切**（顶部最新价 + K 线 + 均线），另一个口径降为小字对照。放弃「只切图表、顶部固定后复权」：那样会出现「图上 5 元、顶上写 10 元」的割裂。
- **[决策·已定]** **均线与所选口径同源**：不复权模式下均线用不复权收盘价计算，除权日保留真实断层（与行情软件的不复权视图一致）。放弃「沿用后复权均线叠加不复权 K 线」：除权处会凭空多出穿越。
- **[决策·已定]** 不复权模式的 `adjustNote` 额外提示「规则求值仍用后复权价」——不复权视图里的均线穿越不代表规则触发。
- **[决策·已定]** 不新增也不修改 ADR：ADR 0005 第 7 条已写明「展示层展示什么口径由界面决定，计算层只认后复权序列」，本次变更在其覆盖范围内；落盘仍只存不复权价 + 后复权因子。
- **[决策·已定]** 不走 `/zh-to-spec` + 拆票，直接在当前上下文实现：改动集中在一个接口 + 一个页面，单会话可完成。
- **[契约]** `GET /api/v1/stocks/{code}/detail` 新增查询参数 `adjust=back|raw`（默认 `back`，非法值 400，报「未知的价格口径」）；`data.adjust` 回显口径；`latest` 由「`close` + `rawClose`」改为三价齐全——`close` 跟随所选口径、`rawClose` 不复权、`adjClose` 后复权。

> 依据：用户「整页一起切（推荐）」；用户「同口径重算（推荐）」；Agent「ADR 0005 第 7 条（展示层口径由界面决定）已覆盖此变更，不改 ADR」；Agent「`adjust=back|raw`（默认 `back`），非法值 400」。

## 2026-11-27 11:03

- **[变更]** 继复权切换后新增需求：把 8 个主要指数像股票一样管理（独立目录存储、可加入自选），且取数**不得拉全市场日 K 文件，只能取单个指数指定日期区间**。已实现。
- **[决策·已定]** 存储布局：`data/parquet/index/<code>.parquet` **一只一文件**，不与股票共用按年分区。理由：指数写入单位本来就是单只、回补某只不碰其他、详情只读一个文件；用户在这一条上没给结论，问的是「同一入口同一界面怎么存方便查询」，因此按查询成本选了这一版。代价：两套目录/两套 schema/两个 store，查询层按 `kind` 路由。
- **[决策·已定]** 自选**一份清单 + `kind` 字段**（`stock`/`index`，旧文件无该字段按股票），不做两份清单。理由：自选是「我要盯的东西」，一份才符合心智，删改只有一处。
- **[决策·已定]** **规则与预警不覆盖指数**：`rule_eval.scope_codes` 与 `rules._watchlist` 只取自选里的股票；指数不能作为单只规则的目标（400「指数暂不支持规则预警」）。代价：指数只能看盘，不能预警。
- **[决策·已定]** 添加指数时**一次回补全历史**（自 2006 年起，单只一次调用）；回补失败不撤销这次添加，失败原因放条目的 `historyError`。
- **[决策·已定]** 指数增量进收盘流水线，新增 `indexes` 阶段（只跑自选里的指数），单只失败只记阶段失败、不阻断求值与日报；`daily_update` 命令同样补一次指数增量。
- **[决策·已定]** 指数详情**隐藏复权开关**，标注「指数没有除权，价格即指数点位」；不做「两个口径同值」的假开关。
- **[决策·已定]** 指数代码**必须带市场前缀**（`normalize_index_code` 拒绝裸 6 位）。裸代码若「数字命中指数清单、股票字典里又没有这只票」（如 `000300`）直接 400 要求补前缀；`000001`/`000016` 因股票字典确有该票仍按股票处理。（这一条是 Agent 自行决定，用户未表态）
- **[决策·已定]** 指数**不归档原始 CSV**，与股票规则不同：单只区间取数可随时重取、Parquet 行与源字段一一对应；股票保留 CSV 是因为全市场横截面重取昂贵。据此写 ADR 0010，并在 `quant/AGENTS.md` 把「所有行情必经 `Ingestor`」标注为指数例外。
- **[事实]** 指数请求 18 列会返回占位值：`peTTM/pbMRQ/psTTM/pcfNcfTTM` 全为 `0.000000`、`tradestatus` 恒 1、`isST` 恒 0、`turn` 有数值但分母对指数没有确定含义（`sh.000001` 217 个交易日样本）。因此只存 10 列，不存复权因子。
- **[契约]** 自选条目新增 `kind`；`POST /watchlist` 接受可选 `kind`（空则按代码判断）；搜索结果项新增 `kind`；`GET /stocks/{code}/detail` 响应新增 `kind`（`stock`/`index`）；流水线阶段顺序变为 `ingest → indexes → evaluate → report`。
- **[风险]** 指数没有原始 CSV 归档，数据源改字段或要重算时只能重取；数据状态页的总行数仍只统计股票。
- **[待办]** 指数暂不支持预警（已明确不做，等看盘需求出现再评估）；`tests/test_index_probe_manual.py` 是他人留下的联网探针（默认跳过），未纳入本次提交。

> 依据：用户「将表格中的指数像股票数据一样管理，分不同文件夹存储。指数也能自选添加…只能获取单个指数的指定日期内的数据」；用户「Q1、用户在操作时用同一个入口，同一个界面，应该怎样存储方便查询 / Q2、A / Q3、A / Q4、A / Q5、A / Q6、A，隐藏或者禁用」；Agent「一只一文件…回补某一只时只重写它自己」。
