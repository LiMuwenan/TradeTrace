# 0003 家庭局域网部署、ntfy 推送与双端分工

- 状态：已接受
- 日期：2026-11-16

## 背景

单用户自用，不做登录。服务部署在家庭局域网内，机器能出网但没有公网入口。Android 端需要收到预警，而国产 Android 上 FCM 通常不可用。

推送的本质是手机维持一条到**公网可达地址**的长连接；这个端点不必是自己部署的。

## 决策

1. **部署**：家庭局域网，单用户，无鉴权，无多租户。
2. **推送通道**：服务端出网 POST 到 **ntfy** 主题，手机用 ntfy 客户端接收；**邮件作为兜底**，避免推送失败时漏消息。
3. **通知体自带数据**：标题 + 标的 + 触发的规则 + 触发价 + 阈值 + 数据日期，不打开 App 也能判断。
4. **双端分工**：Web 负责配置（自选管理、规则配置、日报、指标全集）；Android 只做两页——预警列表（已读/未读）与预警详情（触发快照），个股详情跳转浏览器打开 Web。
5. 推送通道做成可替换的接口，ntfy 与邮件是两个实现。

## 备选方案

| 方案 | 未采用的原因 |
|---|---|
| 厂商推送 SDK（极光/个推/华为等） | 需开发者账号、App 签名，部分通道要求上架或企业资质；单用户不划算 |
| 公网 VPS 自建推送 + 隧道 | 需要长期运维公网服务，与「家庭部署」冲突 |
| 仅邮件 | 延迟与可读性差，不能作为唯一通道 |
| 只做弱触达（打开 App 才看到） | 会让「预警」退化为「分析结果」，产品失去核心价值 |
| Android 完整复刻 Web | 两端都要跟着改，维护成本失控 |
| Android 三页（含自选行情列表） | 在只做「消费」的定位下优先级低于预警链路 |

## 后果

- 离开家庭局域网时，App 只能看到通知携带的信息；点进详情需要回家或在同一网络。
- ntfy 主题是一个可被猜到的地址，主题名需足够随机；消息经第三方服务器中转。
- 若将来改为多用户或公网访问，鉴权、配额、推送通道三处都要重做。
- 请求层需要区分「Web 可用但 App 不可用」的场景，避免 App 在无网时反复失败重试。
- **待定（2026-11-20）**：接收端手机是否有 Google 服务尚未确认。若为无 GMS 的国产手机，ntfy.sh 依赖 FCM 的即时送达会失效，需改为自建 ntfy + WebSocket 保活，或换飞书/企微机器人。发送端不受影响：P0 先只做发送，用 ntfy Web 页面与邮件验证链路，手机端确定后只需改配置。
