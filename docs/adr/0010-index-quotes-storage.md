# 0010 指数行情独立目录存储，按单只区间取数且不进规则范围

- 状态：已接受
- 日期：2026-11-27

## 背景

用户要求指数像股票一样管理（可加入自选、可看日 K），但明确约束：**取数不得拉整个市场的日 K 文件，只能取单个指数指定日期区间的数据**。

现状与此约束并不冲突，只是两条取数路本来就不同：

- 全市场日 K 接口 `query_daily_history_k_AStock(date)` **只含 A 股**，样例 `2026-06-15.csv` 里没有 `sh.000001`（见 `.scratch/quant-p0/02-ingest-and-store.md`）；
- 指数只能用 `query_history_k_data_plus(code, fields, start_date, end_date, frequency="d", adjustflag="3")` 逐只取。核心 10 列 `date/code/open/high/low/close/preclose/volume/amount/pctChg` 全部有值；若硬要 18 列，返回的是**占位值**：`peTTM/pbMRQ/psTTM/pcfNcfTTM` 全为 `0.000000`，`tradestatus` 恒为 1、`isST` 恒为 0，`turn` 虽有数值但分母（换手率要流通股本）对指数没有确定含义。这些列不参与任何计算。

（依据：`sh.000001` 2026-01-05 ~ 2026-11-26 共 217 个交易日的样本，见 `backend/tests/test_index_probe_manual.py` 的联网探针。）

而 `quant` 现有的落盘契约是为股票设计的：19 列（18 列日 K + `back_factor`）、按年分区、所有行情必经 `Ingestor`。指数套不进去。

## 决策

1. **独立目录、一只一文件**：指数日线存 `data/parquet/index/<code>.parquet`，按日期排序，与股票的年度分区目录完全分开。
2. **独立 schema（10 列）**：`INDEX_COLUMNS` / `INDEX_SCHEMA`，不往 19 列里塞空列，也不写 `back_factor`（恒为 1 的因子是噪声）。
3. **唯一取数入口** `app/services/index_quotes.py`：`sync_range(code, start, end)`、`ensure_history(code)`、`sync_watchlist(trade_date)`，全部按「单只 + 显式区间」调用，不存在全市场批量路径。
4. **不归档原始 CSV**：指数是单只一次调用、可随时重取，Parquet 行与源字段一一对应（没有因子派生）。股票之所以保留原始 CSV，是因为全市场横截面重取一次很贵，两者前提不同。
5. **指数代码必须带市场前缀**：`normalize_index_code` 拒绝裸 6 位。`000001` 既是上证指数（`sh.000001`）也是平安银行（`sz.000001`），裸代码只能靠「按首位推断交易所」，必然出错。
6. **可加入自选，不参与规则**：自选条目加 `kind`（`stock` / `index`）；指数详情页只有一条价格序列（点位），因此没有复权切换。规则求值只遍历 `kind=stock` 的条目，指数不能作为单只规则的目标。
7. **收盘流水线加 `indexes` 阶段**：只补自选里的指数，单只失败只记该阶段失败，不阻断求值与日报。

## 备选方案

| 方案 | 未采用的原因 |
|---|---|
| 复用 19 列股票 schema，空列填空 | 契约里多出一堆「不适用」；`tradestatus=1` 是编造值，后续读数的人无法分辨真假 |
| 指数共用一套按年分区（`index/YYYY.parquet`） | 写入单位本来是单只指数，回补一只会重写整年文件，还要 glob 全部年份 |
| 归档原始 CSV 再入库 | 单只区间取数极便宜且幂等，多一份副本只增加不一致的可能 |
| 把指数纳入规则与预警 | 判定链要按数据源分叉（无停牌、无复权、无换手），等于把 05 的判定复制一遍 |
| 允许裸代码并靠首位猜交易所 | `000001`/`000300` 会猜成深市股票，静默建出查不到行情的自选 |

## 后果

- 行情目录变成两套（股票按年、指数按只）、schema 两套、store 两个：查询层要按 `kind` 路由，自选摘要、详情、删除各有一处分支。
- 指数数据**无法从 Parquet 之外重建**（没有原始 CSV 归档）。数据源若改字段或需要重算，只能重取。
- 删除自选指数不删行情：重新添加即时可见，重拉历史才需要联网。
- 未做且明确不做：指数复权（无意义）、指数规则与预警（等看盘需求出现再评估）。

## 修订记录

- 2026-11-27：初版。
- 2026-11-27：补三条取数纪律（对应 03 号票）——
  1. **分段**：一次区间不超过 5 年。整段 2006→今天（约 5000 行）拉到中途会被数据源关掉连接，分段后每段独立落盘，失败点之前的进度是真的。
  2. **串行**：baostock 客户端是进程级全局 socket，并发取数会互相踢会话，因此进程内所有指数取数走同一把可重入锁。
  3. **后台**：加入自选立刻返回，回补在后台线程跑（`POST /stocks/{code}/history` 可重试、可续补）。同步拉 20 年会让「加入」这个动作看起来没有反应。
  失败即停而非跳过：后续段依赖同一条连接，继续只会重复同一个错误。运行态只在进程内保存，重启后靠「补数据」或下一次流水线补缺口。
