# 0002 预警采用日频边沿触发模型

- 状态：已接受
- 日期：2026-11-16

## 背景

预警是这个产品的核心。若判定模型选错，用户会关掉通知，产品随之失去价值。数据源仅 baostock，只提供日线，没有实时行情。

## 决策

1. **日频求值**：每个交易日收盘后计算全部规则，结果供次日盘前提醒使用；不做盘中实时。
2. **边沿触发**：每条「标的 + 规则」维护一个触发态，只在「不满足 → 满足」的那一刻产生一条预警；回落到「不满足」之后，才可能再次触发。
3. **每日上限 + 日报兜底**：单日推送条数设上限；未被推送的命中项合并进当日日报。
4. 规则由「标的范围 + 指标 + 阈值 + 时间窗」构成；P0 支持突破、超跌、放量、均线四类。

## 备选方案

| 方案 | 未采用的原因 |
|---|---|
| 电平触发（满足即每天记一条） | 连续五天放量会产生五条，通知会被淹没 |
| 只出日报，不逐条预警 | 丢失「尽早知道」的价值 |
| 盘中实时预警 | 需要另一套实时数据源，成本与稳定性风险陡增；与「数据分析」而非「盯盘」的定位不符 |

## 后果

- 预警的时效上限是「次日盘前」，无法覆盖盘中突发事件。
- 数据模型必须包含触发态（按标的 + 规则维度的布尔与时间戳），这不是可以后补的字段。
- 规则引擎必须可重跑：重算同一天不能重复产出预警（幂等）。
- 若将来引入实时行情，需要把「按交易日求值」改成「按事件求值」，属于结构性改动。
