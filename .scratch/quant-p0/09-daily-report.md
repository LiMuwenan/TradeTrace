## 要做什么

每个交易日收盘求值后，生成一份当日汇总，作为「当天什么都没触发」时的兜底触达，以及在 Web 上回看当日全貌的入口。

## 验收标准

- [x] 每个交易日生成一份日报，**无论当天是否产生预警都生成**
- [x] 日报包含：当日触发清单、接近阈值但未触发的清单、自选涨跌概览、数据日期
- [x] 接近阈值项按 05 票定义的口径计算（差距在阈值 20% 以内）
- [x] 日报通过与预警相同的通知通道投递（ntfy，失败降级邮件）
- [x] Web 可回看历史日报，按日期列表进入
- [x] 日报内容不可被后续求值改写（同一天重跑只更新未投递的草稿，已投递的保留原文）
- [x] 日报带「不构成投资建议」提示

## 备注

- 日报与逐条预警是两条独立的触达路径：逐条负责「尽早知道」，日报负责「不漏」
- 日报生成失败不应影响已发出的逐条预警
- 邮件正文用纯文本或简单 HTML 皆可，不要求 PDF 导出（P0 范围外）
- **2026-11-26：本票顺延到下一迭代**。在此之前没有日报，ADR 0002「超限命中项合并进日报」的兜底暂缺，08 必须先定超限项的去处（见 ADR `0006-p0-scope-convergence.md`）

**实施记录**（2026-11-26）：生成与投递在 `app/services/report.py`，存储 `app/storage/report_store.py`（`daily_report` 表，`trade_date` 主键），正文在 `app/services/notify.py` 的 `report_text` / `report_subject`，路由 `POST /reports/generate`、`GET /reports`、`GET /reports/{date}`。前端 `ReportsPage.vue` + `ReportDetailPage.vue`。

**四处实现判断**：

- 日报读的是**当日全部真实预警**，而不是「还没推送的那几条」。超限被跳过、推送失败的记录都必须出现在日报里，否则「没收到通知」就等于「没发生」——这正是日报存在的意义。
- 「已投递不改写」用 `daily_report.pushed_at` 判定：已投递直接返回原文，连重算都跳过；未投递才允许覆盖草稿。这样用户昨晚收到的邮件和今天在 Web 上看到的必然是同一份。
- 接近阈值直接复用 `rule_eval.is_near`，不另立一套口径；`_scope_codes` 因此提升为公开的 `scope_codes`，日报和求值共用同一套范围判定。
- 投递复用预警的 ntfy → 邮件降级链（`AlertNotifier.send_report`），但 `notification_log.event_id` 记空，**不占每日 50 条的预警额度**——日报不是一条预警，占了额度会挤掉真正的提醒。
- 正文最多列 20 条，超出写「另有 N 条，见 Web 日报」，避免超过 ntfy 的正文长度限制。
