## 要做什么

预警产生后，把消息送到用户手机上。用户多数时间在外网，手机无法访问家庭局域网内的服务，因此**通知内容本身必须自足**。

## 验收标准

- [ ] 预警产生后通过 ntfy 推送，手机可收到
- [ ] 通知内容包含：标的代码与名称、规则名称、触发值、阈值、数据日期，以及「不构成投资建议」提示
- [ ] ntfy 发送失败时降级为邮件发送，同一条预警不会因为降级而丢失
- [ ] 存在每日推送上限（默认 50 条，设置页可改），超出的预警只落库不推送，在 Web 预警列表中照常可见
- [ ] 通知设置页可配置：ntfy 服务地址与主题、收件邮箱、每日上限开关
- [ ] 可发送测试通知，验证配置是否可用
- [ ] 每条通知的发送结果（成功/失败/降级）有记录可查

## 备注

**部署约束**：服务运行在局域网内，不能接收公网入站请求，因此不使用自建长连接推送；ntfy 作为出站 HTTP 调用即可满足。

**安全约束**：ntfy 主题名是「知道地址即可订阅」，必须使用足够长的随机串，并在设置页提示这一风险。

**内容约束**：手机在无服务端网络的情况下收到推送，若通知只有标题，用户无法判断是否值得回家查看，因此正文必须带齐关键数据。

**不做**：App 内推送通道、第三方推送 SDK、Webhook 群机器人，均在 P0 范围外。

**接收端待定**：手机是否有 Google 服务尚未确认。本票只实现发送端，验证方式是 ntfy Web 页面订阅 + 邮件。若最终为无 GMS 手机，接收侧需改自建 ntfy（WebSocket）或换飞书/企微机器人；届时只改配置与接收端，不动本票的发送逻辑。

**上限口径（2026-11-26 修订）**：默认上限由 10 条改为 **50 条（暂定值，非常量，随配置下发）**。原「超限项合并进次日日报」因 09 日报顺延而暂无载体（见 ADR 0006），P0 期间由 Web 预警列表承担，日报上线后切回日报。

**推送对象**：只推 `rule_state_event` 中 `event = 'enter'` 且 `replayed = 0` 的行（ADR `0007-rule-state-event-stream.md`）。静默回放产生的历史触发一律不推，`exit` 记录不产生通知。
