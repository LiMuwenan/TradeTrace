## 要做什么

实现四类预警规则的求值，以及「一次触发」的判定语义。这是产品的核心：决定用户会不会因为通知太吵而关掉。

求值以「某一交易日」为单位全量跑一遍自选范围，产出触发记录并落库；同一天重跑不产生重复记录。

## 验收标准

- [x] 支持四类规则：突破、超跌、放量（含缩量）、均线穿越，每类可配置时间窗与阈值
- [x] **边沿触发**：每个「标的 + 规则」记录当前是否处于触发态，只在「未触发 → 触发」的瞬间产生一条预警；持续满足不重复产生；回落到未触发后再次满足可再触发
- [x] **幂等**：同一交易日重复求值，不产生重复预警记录
- [x] 停牌标的（当日停牌）不参与求值，不产生预警
- [x] 求值范围默认为自选清单，可指定为单只标的用于调试
- [x] 每条预警记录保存触发快照：触发时的指标值、阈值、使用的价格、数据日期
- [x] 可查询某标的某规则的触发历史，能看到「何时进入触发态、何时解除」
- [x] 求值耗时在 100 只自选、1 年数据下不超过 5 秒

## 备注

**规则口径（P0 固定，不做可视化公式编辑器）**：

| 规则 | 判定 | 默认参数 |
|---|---|---|
| 突破 | 当日收盘价 > 前 N 日最高收盘价 | N=60 |
| 超跌 | (前 N 日最高收盘 − 当日收盘) / 前 N 日最高收盘 ≥ 阈值 | N=60，阈值 20% |
| 放量 | 当日成交量 / 前 N 日均量（均量不含当日）≥ 阈值 | N=5，阈值 1.5 |
| 缩量 | 同上比值 ≤ 阈值 | N=5，阈值 0.6 |
| 均线穿越 | 收盘价由下向上穿越 MA(N) 为触发；向下穿越为解除 | N=20 |

- 所有跨日比较必须使用**后复权**价格序列；涨跌幅用数据源字段，不由收盘价自算
- 「前 N 日均量」不含当日，避免当日成交量把分母抬高
- 「接近阈值」定义为：方向一致但未达阈值，且差距在阈值的 20% 以内（仅供后续日报使用，本票只需可计算，不展示）
- 时间窗不足 N 日的新股或次新股不参与该类规则，不产生预警
- 触发态的唯一键是「标的 + 规则」；预警记录的唯一键是「标的 + 规则 + 交易日」

**每日推送上限**不在此票实现，属通知票。

**求值入口**（2026-11-26 决定）：本票只提供手动 HTTP 入口 `POST /api/v1/rules/evaluate`，参数为必填 `date` 与可选 `code`（指定单只标的用于调试），**不做内建定时器**；每日自动触发由 10 号票的调度实现。重复调用同一天必须幂等。

**状态与记录的存储**（ADR `0007-rule-state-event-stream.md`）：单表 `rule_state_event`，落在 `{meta_dir}/meta.db`（SQLite）。一次求值对每个「标的 + 规则」最多写一条事件，`event` 为 `enter` 或 `exit`，唯一键「标的 + 规则 + 交易日」。**预警就是 `enter` 行**，推送/已读状态是这一行的列；**触发态不落库**，由最后一条事件推导。本票不新建第二张预警表。

**静默回放**：本票还需提供 `POST /api/v1/rules/{id}/replay`，只写事件、不推送，`enter` 行标记 `replayed = 1`。由 06 在规则启用时调用；回放结束后该规则状态与历史触发次数即为真实值。验收标准第 7 条的「何时解除」由此满足。

**回放起点**（2026-11-26 修订，撤销当日早先的「最短时间窗」决定）：起点取**该规则能算出结果的最早一天**（突破/超跌/量比类为 `window`，均线类为 `window-1`），一直走到启用前一日，与 ADR 0007 决策 6 一致。

原口径「只从距今 N 个交易日起算」在实现时被证伪：若条件在整段窗口内一直成立，回放看不到「由假变真」的那一刻，触发态会被推成「未触发」，次日求值立刻产生一条假预警。因此回放覆盖全历史，「历史触发次数」也按全历史统计，不得表述为「近 N 日窗口内」。

**规则来源**（2026-11-26 决定）：本票先建 `alert_rule` 表（表结构与 06 一致），并支持从 `config/rules.example.toml` 一类的配置文件导入种子规则，用于 06 的 UI 上线前调试。**这条导入路径是临时后门**，06 完成后删除；不可成为第二条长期写入口。

> **2026-11-26 已删除**：06 上线时移除了 `app/import_rules.py`、`config/rules.example.toml` 与 `rule_store.import_seed_rules`。规则定义现在只有一个写入口 —— `app/services/rules.py`（Web 规则页）。

**推送收尾**（ADR `0008-evaluate-invokes-notify.md`）：求值写库提交后，在同一请求内同步调用 08 的通知服务，投递本次产生的 `enter`、`replayed=0`、`pushed_at` 为空的行；通知异常必须兜住，不得回滚或影响求值结果，接口响应另给推送摘要（成功数 / 失败数）。

**实施记录**（2026-11-26）：接口为 `POST /rules/evaluate`、`POST /rules/{id}/replay`、`GET /rules/{id}/history`；求值集中在 `app/services/rule_eval.py`，存储 `app/storage/meta_db.py` + `rule_store.py`。基准：100 只自选 × 250 交易日 × 5 类规则，单日求值 **2.87s**（含 100 次 Parquet 查询与 61 条推送尝试），满足 5 秒约束；导入同规模数据耗时 16.5s 属 02 号票范围。

**审查修正**（2026-11-26）：① 事件唯一键扩为 `(标的, 规则, 交易日, event)`——人工收尾的 `exit` 会与当日 `enter` 撞日期（ADR 0007 修订说明）；② 「接近阈值」由 `is_near()` 实现，本票只提供计算、不展示，供 09 日报使用；③ 新增 `rule_store.close_states()` 供 06 在改参数/停用时写带 `reason` 的 `exit`；④ 调试用 `code` 参数不再覆盖「指定单只」规则；⑤ 首次能算出结果的那天按「未触发」起算——这正是新规则必须先回放的原因。
