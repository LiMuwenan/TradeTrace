## 要做什么

用户在 Web 上自助创建、修改、停用预警规则，不需要改配置文件或写 SQL。

## 验收标准

- [x] 可新建规则：选规则类型、标的范围、时间窗、阈值
- [x] 可修改已有规则的阈值与时间窗，修改后从下一个求值日生效，历史预警不受影响
- [x] 可停用规则：停用后不再参与求值；历史预警记录仍然保留可查
- [x] 表单校验：时间窗不得小于 2；阈值限定在合理区间（放量 > 0、超跌在 0～100% 之间），越界时给出具体提示
- [x] 规则列表展示：类型、标的范围、关键参数、启用状态、最近一次触发时间
- [x] 新建与修改后能看到该规则覆盖了多少只标的

## 备注

- 编辑体验以表单为主，不做自然语言规则生成，也不做公式编辑器
- 标的范围 P0 只支持「全部自选」与「指定单只标的」两种
- 规则与预警记录的关系：修改规则不追溯历史预警；历史预警保留当时的快照值
- **规则定义落 `{meta_dir}/meta.db` 的 `alert_rule` 表**（ADR `0007-rule-state-event-stream.md`），与触发态变更记录同库同文件
- **新建并启用规则时**：必须先调 05 的 `POST /api/v1/rules/{id}/replay` 做静默回放，回放完成后才允许该规则参与每日求值；回放期间界面要给出「正在计算历史状态」的明确提示，不能静默卡住
- **修改阈值/时间窗、停用规则时**：调用 05 提供的 `rule_store.close_states(rule_id, reason=...)` 写一条 `exit` 收尾，`reason` 分别为 `rule_changed` / `rule_disabled`，新参数从次日求值起算
- **本票上线时须删除 05 里的配置文件种子导入路径**（见 05 备注），规则从此只有一个写入口：本页表单

**实施记录**（2026-11-26）：管理逻辑在 `app/services/rules.py`（列表聚合、新建即回放、改参数收尾、启停），路由在 `app/api/rules.py`（`GET /rules`、`POST /rules`、`PUT /rules/{id}`、`POST /rules/{id}/enabled`），前端 `web/src/components/RulesPage.vue`。

**三处实现判断**：

- 新建时先建为停用态、回放成功后才启用。回放失败则规则留在停用态，用户可在列表里重试启用——比「建好了但状态算错的规则在跑」安全。
- 重新启用已停用的规则时，回放截止日传「启用日」而非创建日（`replay_rule(until=...)`），把停用期间漏掉的历史一并补上，仍标 `replayed=1` 不推送。
- 只改名称不写 `exit`；只有时间窗或阈值变化才按旧口径收尾（`reason=rule_changed`）。标的范围不可原地修改，要换范围必须新建。
